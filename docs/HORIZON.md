# BetterInstincts horizon — living trajectory and execution authority

This is the long-term product outcome, not a command to implement everything immediately. Source-of-truth dependency machine: [plans/horizon.v1.json](../plans/horizon.v1.json); validation: `python -m scripts.check_horizon`. Source of domain vocabulary: `contracts/needs.v1.json`. Exact game-version profiles and immutable prior certifications: [COMPATIBILITY.md](COMPATIBILITY.md). Parent vision in [LEDGER.md](LEDGER.md).

## Delivery trajectory
1. **BI-002: Hunger** — finish the first actual reversible Sims tuning package, >=5 vanilla and >=5 modified gameplay trials, rollback and maintainer review. Cannot close based on offline CI.
2. **BI-003A–E: The other five adult needs** — bladder, energy, hygiene, fun and social. Each module needs its own real tuning resource, reversible package, valid full game-version profile, observed A/B comparison, and no player command interruption. After the BI-002 mechanism is live-proven, these five *investigations* may proceed as independent branches if actual workers and collision-free tuning ownership are established. Never reuse the hunger resource ID for another need.
3. **BI-003F: Whole-needs balance** — simultaneously test all six, including low-need collisions, shared actions that satisfy two motives, adults with varied traits, edge cases and mod conflicts. Prevent thrashing, starving one need while optimizing another, all-Sims-identical behavior, player queue cancellation, and uncontrolled simulation overhead. Individual module success **does not** certify combined success.
4. **BI-004: Sustainable income** — alongside maintenance of each needs module, discover *genuinely available* income-generating activities, work time and budget constraints; verify actual household-funds changes in game and that repeated opportunities don't start loops. Never claim earnings based on a suggested action alone. No unattended arbitrary job selection, cheats, or exploit mechanics.
5. **BI-005: Skills** — only after income behavior is live-observed: develop purposeful, optional skill-building using available items, aspirations, traits and actual skill increments. Validate skill value changes, time budget, needs protection and continuing income performance. Leave player-directed plans intact; leisure remains a valid outcome.
6. **BI-006: Career advancement** — depend on skill floor: appropriate work attendance/preparation, promotion prerequisites and work-from-home edge cases measured per compatible patch.
7. **BI-007: Household preferences/personality** — separate bounded work after needs balance; preserve individuality, relationships, player overrides and social spontaneity. No broad AI rewrite.
8. **BI-008: Quality maintenance** — version support, isolated patches, safety, performance, conflict matrices, releasing and uninstalling happen throughout, not only at the end.

These phase numbers replace the older roadmap that placed skills inside the career milestone. The new operator priority is unequivocally **needs -> income -> skills -> career**. Do not substitute generic productivity for a balanced, fun Sims experience.

## What is implemented right now (not game-integrated)
`betterinstincts/horizon.py` is a side-effect-free, read-only decision candidate for the **six standard adult motives** Hunger, Bladder, Energy, Hygiene, Fun and Social. Each abstract action must be supplied as available; it never queues interactions. Its guardrails reject busy/player-directed states, unknown life-stage motive sets, unsafe or missing remedies, cooldowns and unknown need values. Its immediate thresholds (0.35, 0.55 on normalized fictional need values) are **hypotheses, not actual tuning**; no claim of real game fit. Income suggestions are gated on explicit `needs_game_certified`; skill suggestions additionally require explicit `income_game_observed`. Those flags must eventually be derived from real version-matched certification, **not** blindly set by caller code. Existing `priority.py` remains the previous four-need comparison floor; never delete it until gameplay evidence supports replacing it.

## Prototype -> measure -> refine (P82)
Selected hypothesis: a minimal six-motive priority engine produces safe eligible recommendations and keeps income/skills behind measured floor gates, whereas four-need baseline doesn't address low Fun/Social. Baseline: `betterinstincts/priority.py`. Candidate: `horizon.py` + one small needs contract. Comparator: `python -m unittest tests.test_horizon -v` and `python -m scripts.eval_horizon`. Reject/refine if any missing basic motive, player override regression, skipped income floor, unavailable needs prompting work, or failed P82 fixtures. Keep it only as **offline prototype** until actual game A/B decides whether it maps to Sims tuning at all. See [P141/P82 decision record](HORIZON_DECISIONS.md).

## Bounded releases and quality regressions
Each patch and module maintains a separately certified immutable profile. A new game patch cannot silently change older working configs. Local evidence must disclose baseline/modified/rollback, explicit full game version, package hashes, tuning identifiers, conflict matrix, performance and human-reviewed observations. No automatic telemetry, save edits, unbounded caches, unknown file writes, or opaque background behavior. Novel child/ghost motives are **not** covered by the six-need adult test ontology and must be scoped and tested separately.

## Progress semantics
`plans/horizon.v1.json` describes *required work* and static dependencies; status is a planning signal, **not** runtime certification. Current active gate is BI-002. `python -m scripts.check_horizon` verifies relationships. Future agents must record game evidence in version-scoped certification records, update the canonical ledger, and only then open successor implementation gates. PR CI validates topology, decision logic and guardrails. Local-game certification remains a separate proof.
