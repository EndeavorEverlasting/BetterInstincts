## Mandatory experiment
1. Preflight git status/branch/HEAD, active PRs, local Sims version and pack set. Preserve unrelated files. Game proof not available? Emit `BLOCKED_LOCAL_GAME_ACCESS` while continuing safe source research only.
2. Using a **disposable save** owned by this experiment, define a controlled test household and repeatable scenario; disable other autonomy mods for vanilla baseline. **Never** modify the user's ordinary game save.
3. Record baseline of >=5 repeatable trials: autonomous time-to-food action after hunger crosses a chosen threshold, lowest observed hunger, interruptions to explicit player commands, stuck/looping interactions, errors, game performance indicators and variance. If game baseline already achieves the goal, document falsification and stop/adjust rather than inventing code.
4. Inspect exact current vanilla hunger/autonomy tuning through Sims 4 Studio. Record tuning resource identifiers, class and score knobs, patch/build, pack requirement, any XML override collision; link proven source. Do not fabricate XML, ID or gameplay API.

If tuning cannot meet acceptance, log the limitation and route the smallest evidence-backed Python script experiment in a new owned sprint.
6. Build local authored `.package` into repo `dist/` only; validate package contents do not redistribute EA assets. Manually copy the reviewed package to a user-chosen `Mods/BetterInstincts/` path on the experiment host. Never install globally/automatically.
7. Restore the disposable save baseline and run >=5 comparable trials with only that change. Record exact artifact SHA-256 and game patch. Require **zero** interruptions of explicit player commands, zero repeated autonomous loops, no new exceptions or meaningful sim lag, and materially improved timely eating versus baseline.
8. Disable/remove only the authored package; repeat smoke test on disposable save to prove safe removal and restored baseline behavior. Test optional mod interactions (Smarter Self-Care, MCCC, other overriding packages) **separately** and report unknown when not tested.
9. Add a reproducible fixture or deterministic source validation where feasible, document the experiment results including failures, then commit on a bounded branch, push, open PR, validate, and integrate only the proven slice. **Do not publish a release** before docs/VALIDATION.md publication requirements are satisfied.

## Decision and proof
- **PROMOTE:** observable, repeatable hunger improvement, safe player queue, patch-specific compatibility and rollback validated.
- **WEAKEN/REVISE:** no meaningful difference, collisions, poor simulation performance, surprising player-control effects.
- **REJECT:** measured negative player impact or incompatibility that cannot be fixed safely within scope.
- **BLOCKED:** no game/tool access, unclear Mods directory or authoring resource. Human local validation is a real boundary, not evidence the policy already works.
